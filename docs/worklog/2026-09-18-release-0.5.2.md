# 0.5.2 の公開 — 変わった 2 つだけを出す

2026-09-18。main は `7be7b86`（`highlight` の merge）。`2026-09-18-highlight.md` の「版と文書」が
「この版を publish しないと H1 以降が使えない」と書いて残していた公開を済ませた記録。

## 1. 公開前の状態

`Cargo.toml` の版と crates.io の `max_version` を並べたもの（crates.io の API
`/api/v1/crates/<name>` で取った）。

| crate | main の版 | crates.io | |
|---|---|---|---|
| `sabiruby` | 0.5.2 | 0.5.1 | 未公開 |
| `sabiruby-compiler` | 0.2.3 | 0.2.2 | 未公開 |
| `sabiruby-cli` | 0.5.0 | 0.5.0 | 同じ |
| `sabiruby-macros` | 0.1.0 | 0.1.0 | 同じ |
| `sabiruby-serde` | 0.1.0 | 0.1.0 | 同じ |

`v0.5.1`（`60e1816`）から main までは 9 コミットで、`git diff --stat v0.5.1..HEAD` が差分を
出すのは `compiler/`（6 ファイル、+505 −2。`highlight()`）とルートの `Cargo.toml` の 1 行（版）
だけである。`src/`、`cli/`、`macros/`、`serde/` は 1 行も出ない。だから出すのは上の 2 つで、
残り 3 つは公開済みの版がそのまま最新になる。

## 2. 順序 — 今回は compiler が先でよい

0.5.0 のときの順序は macros → VM → compiler → serde → cli だった
（`2026-09-17-release-0.5.md` の 4 節）。今回 2 つだけを出すときに効くのは、この 2 つの間の
依存だけである。

* `sabiruby-compiler` → `sabiruby`: `version = "0.5.0"`、optional（feature `host`）。
  `^0.5.0` は公開済みの 0.5.1 で解決できるので、**compiler は VM の 0.5.2 を待たない**。
* `sabiruby` → `sabiruby-compiler`: dev-dependency で、path だけで版が無い。packaging で
  落とされるので、VM の公開は compiler の版に依らない（`docs/design/compiler.md` の
  "Publishing" の最後の段落が言っていること）。

つまりどちらが先でも通る。中身が変わったのは compiler なので compiler を先にした。

`sabiruby-cli` 0.5.0 は `sabiruby ^0.5.0` と `sabiruby-compiler ^0.2.2` を名指ししているので、
これから `cargo install sabiruby-cli` する人には 0.5.2 と 0.2.3 が入る。cli を出し直す必要は
無い。

## 3. やったこと

```
cargo publish --dry-run -p sabiruby-compiler   # Packaged 94 files, 3.0MiB (405.4KiB compressed)、verify 通過
cargo publish --dry-run -p sabiruby            # Packaged 151 files, 2.3MiB (709.9KiB compressed)、verify 通過
cargo publish -p sabiruby-compiler             # Published sabiruby-compiler v0.2.3 at registry `crates-io`
cargo publish -p sabiruby                      # Published sabiruby v0.5.2 at registry `crates-io`
git tag -a v0.5.2 -m "SabiRuby 0.5.2: sabiruby-compiler 0.2.3 with highlight()" 7be7b86
git push origin v0.5.2
```

作業ツリーは clean、`main` は `origin/main` と同じ位置で打った。cargo は 1.97.0。
公開後にもう一度 API を引いて `sabiruby` 0.5.2、`sabiruby-compiler` 0.2.3 を確かめた。

dry-run の警告は「`tests/*.rs` が package に入っていないのでテストを無視する」だけで、
これは以前の公開と同じ（テストは crate に同梱していない）。

タグは `v0.5.0`・`v0.5.1` と同じ注釈付きで、リポジトリの release の名前（＝ VM の版）で打つ。
compiler の版はタグの名前には出ないので、メッセージに書いた。

## 4. 使う側

* **rubevy / rubevy_games** は `sabiruby` も `sabiruby-compiler` も git 依存
  （`https://github.com/sabiruby/sabiruby`）なので、crates.io の版には依らない。`highlight()` は
  `663f3f2`（rubevy_games、SabiRuby を `7be7b86` に）で既に使えていた。今回の公開で変わる
  ものは無い。
* **sabiruby-playground** は path 依存（`../../sabiruby`。CI は隣に checkout する）なので、
  これも crates.io の版には依らない。
* **crates.io から使う人**は、`sabiruby-compiler = "0.2"` のまま `cargo update` で
  `highlight()` が手に入る。README の依存の例（`"0.5"`、`"0.2"`、`"0.1"`）は書き換え不要。

## 5. 残っていること

* `rubevy`（0.0.1）と `rubevy-arena`（0.1.0）は crates.io に無い。git 依存のまま公開は
  できない（crates.io は git 依存を受け付けない）ので、出すなら依存を版に書き換える作業が
  先に要る。今回は触っていない。
