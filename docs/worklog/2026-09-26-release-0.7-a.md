## 1. S1: Hash の探索が `eql?` の例外を捨てる

### 読んだところ

`Vm::hash_get`（`src/vm.rs`、変更前 4616 行）は `hash_index` の `Err` を `_ => None` で、`Vm::hash_delete`（変更前 5003 行）は `.ok()??` で捨てていた。
`hash_index` は `key_hash`（キーの `hash` を Ruby で呼びうる）と `hash_index_at`（候補ごとに `key_eql`、つまり `eql?` を Ruby で呼びうる）を通る。
呼び手は `src/builtins/hash.rs`（`[]`、`fetch`、`key?` ほか 4 つ、`delete`、`eql?`、`==`、`merge!`/`update`、`__delete`、パターン照合の `__pat_values`）、
`ext_hash.rs`（`slice`、`slice!`、`except`）、`ext_set.rs`（`has`、`del`）、`ext_regexp.rs`、`ext_sprintf.rs`、`ext_struct.rs`、
`vm.rs` の `OP_KARG`／`OP_KEYP`／`OP_GETIDX`／`OP_GETIDX0`。外では rubevy の `src/reflect.rs:187` が `vm.hash_get(other, k).unwrap_or(Value::Nil)` と使っている
（rubevy_games と sabiruby-playground は使っていない。`grep -rn "hash_get\|hash_delete"`）。

rc2 の本家は `H_CHECK_MODIFIED`（`src/hash.c:270-347`）で `obj_eql` を包み、表のポインタ・容量・フラグ・要素数のどれかが変わったら
`RuntimeError: hash modified` を出す。要素数の比較は GHSA-2778-fvwg-5m8w で足された（`struct h_check_modified` の `size` のコメント）。

### 本家での確かめ

スクラッチの `s1.rb`／`s1b.rb`（`eql?` が `ArgumentError` を出し、`hash` は `"k0".hash` を返すキー）を rc2 で走らせた:
`[]`、`key?`、`fetch`、`delete`、`include?`、`member?`、`has_key?`、`[]=`、`dig`、`values_at`、`slice`、`except`、`merge!`、`update`、`==`、`eql?`、`store`
がすべて `ArgumentError: boom`。`{"k0"=>1} == {b=>1}`（受け手の側のキーが String）は `false`（String の `eql?` はネイティブで、`b.eql?` は呼ばれない）。
`Set#include?`／`Set#delete` は例外を出さずに「無い」と答える。`mrbgems/mruby-set/src/set.c:58-85` の `kset_equal_value` が `mrb_protect_error` で包んで、
例外なら not-equal にしている。変更前の SabiRuby は Hash の側がすべて `nil`／`false`／`:d` だった（`merge!`、`update`、`[]=`、`store` は `hash_set` が `?` で通すので例外が出ていた）。

### 決めたこと: 案 (a)

rc2 の worklog（`2026-09-23-rc2.md` 3 節）の案から (a) を取った。つまり:

1. `hash_get`／`hash_delete` を `VmResult<Option<Value>>` にして、`hash`／`eql?` の例外を呼び手に届ける。
2. `hash_index_at` で `eql?` を Ruby で呼んだ後に要素数を比べ、変わっていたら `RuntimeError: hash modified`。
3. ハッシュ値の違うキーにも `eql?` をかける (b) はしない。rc2 の `hash` の assert（キーの `hash` が 0）は今までどおり通らず、分類を undecided から deviation にした。

理由: 本家は例外を出す（計画書が S1 を「不具合」と書いている）。(b) は「小さい表では `eql?` を全要素にかける」という本家の表現の都合を真似ることになり、
探索の意味が表の大きさで変わる（CRuby はハッシュ値を先に比べる）。探索の速さ（stage 2c）にも触れる。backlog に「見直すとき」付きで残した。

### 決めたこと: 公開 API は型を変える

`hash_get`／`hash_delete` の戻り値を `VmResult<Option<Value>>` にした。`try_hash_get` を足して古い方を残す案もあったが、古い方は「例外を黙って捨てる」ままで、
それを直すのが S1 なので残す理由が無い。0.7.0 は挙動の変わるバージョン（0.x の minor 上げ）で、型が変わればホストはコンパイルで気づく。
CHANGELOG の Unreleased に移し方（`.ok().flatten()` か `?`）を書いた。`hash_set` がもともと `VmResult<()>` なのとも揃う。
rubevy の `reflect.rs:187` はこのままでは 0.7.0 で建たない（気づいた点 3）。

### 決めたこと: Set は例外を「無い」にする

`ext_set.rs` の `has`／`del` は `matches!(vm.hash_get(..), Ok(Some(_)))` にした。本家の mruby-set が `mrb_protect_error` で not-equal にしているのに合わせる。
`put`（`hash_set` 経由）は前から例外を通していて、本家は通さずに要素を足す（`Set#add` のずれ。気づいた点 1。範囲の外なので触っていない）。

### 実装

- `key_eql` を 2 つに分け、`eql?` を送る半分を `key_eql_send` にした（`src/vm.rs`）。`hash_index_at` は、キーが String でない Obj のときだけ `key_eql_send` を呼んでその後に要素数を比べ、
  それ以外（整数・シンボル・String）は `self.eql` で前と同じ道を通る。要素数は `first_candidate` を取るのと同じ借用で読むので、ネイティブの比較の道には heap の読みが増えない。
- 要素数の比較は `eql?` が true を返した場合にもかける（本家の `H_CHECK_MODIFIED` は `obj_eql` の結果によらず検査する）。
- 呼び手は `?` で通す。`Hash#eql?` は `eq_guard` を積んでいるので、`Err` でも guard を下ろしてから返す形のまま（`res = Err(e); break`）。

## 2. S2: `funcall` の `method_missing` がクロージャのとき

`Vm::funcall`（`src/vm.rs:2081`）の `None =>` 枝で、`method_missing` が `Method::Closure` のとき `call_closure` をそのまま呼んでいた。
すぐ上の `Some((MethodRef::Closure, _))` 枝は `native_depth` の上限を見て、`native_mid` を置き、`direct_send` を下ろして呼び、戻して、`orphan_block_of_native` をかける。

### 先に落ちるテストを書いた

`tests/native.rs` の `a_closure_method_missing_reached_by_funcall_is_behind_the_native_that_called_it`: Ruby から SEND で呼ばれるクロージャ `relay` が
`vm.funcall(obj, :nope)` し、`Ghost` のクロージャの `method_missing` が `vm.fiber_yield` する。本家では `mrb_funcall` が `CINFO_DIRECT` の frame を積み
（`src/vm.c`、`mrb_funcall_with_block` の `cipush(... CINFO_DIRECT ...)`）、`mrb_fiber_yield` の `fiber_check_cfunc`（`mrbgems/mruby-fiber/src/fiber.c:160-169`）が
`can't cross C function boundary` で断る。C の gem を建てないと本家で走らせられないので、期待値はこのソースから取った。対照として、同じクロージャを SEND で直に呼ぶ `Ghost.new.nope` は yield できる。

変更前:

```
  left: "1\n1\n:done\n"
 right: "\"can't cross C function boundary\"\n1\n:done\n"
```

`relay` の Rust の frame が生きたまま fiber が切り替わり、`resume` が 1 を返していた。

### 直し

`None =>` 枝のクロージャの呼び方を、上の Closure 枝と同じにした（上限、`native_depth`、`direct_send` の出し入れ、`orphan_block_of_native`）。
`native_mid` は `method_missing` にした（決めたこと: そこで走っているネイティブは `method_missing` なので。SEND から Ruby の `method_missing` に回すときも名前は `method_missing`、
`op_send_vis(base, a, mm, ...)`）。変更後はテストが通る。

## 3. S3: rc2 の 2 つの確かめ

### `nlocals > nregs` を読み込みで断る（`7ed51715e`）

`src/rite.rs` の `read_record` は数を読むだけだった。本家の bintest と同じ形の偽の image（`mrbc --remove-lv` で `def m(a); a; end; m(1)` を作り、2 つ目の record の
`nlocals` を `nregs + 1` と `0xffff` に書き換え）を作って並べた:

```
rc2:            (unknown):0: irep load error (ScriptError)      exit=1   （2 本とも）
SabiRuby 変更前: panicked at src/vm.rs:5065:50: index out of bounds: the len is 5 but the index is 5
```

変更前は `OP_ENTER` が `nlocals` まで消そうとして panic していた（Rust なので範囲外は書かないが、ホストごと落ちる）。
`read_record` で `nregs` を読んだ直後に `nlocals > nregs` なら `VmError::Rite("irep record with 5 locals but 4 registers")` を返すようにした。
本家の文言（`irep load error`、ScriptError）に合わせるかは考えたが、SabiRuby の読み込みの誤りはほかも全部 `VmError::Rite` なので、それに揃えた（決めたこと）。

### `OP_CALL` の受け手が Proc でないとき（`78a055595`）

SabiRuby の `Op::Call` は前から Proc かどうかを見て TypeError を出していた（`wrong type (expected Proc)`）。本家は `wrong type %T (expected Proc)`。
bintest と同じ image（`LOADI_0` → `CALL`、`STRING "AAAAAAAA"` → `CALL`）を作って並べた:

```
rc2:            wrong type Integer (expected Proc) (TypeError) / wrong type String (expected Proc) (TypeError)
SabiRuby 変更前: wrong type (expected Proc) (TypeError)（2 本とも）
```

`%T` は SabiRuby の `describe_for_error`（`src/vm.rs` の「mruby's `%T`」）なので、それで文言を作った。本家の `OP_BLKCALL`（`vm.c:3776`）も同じ文言なので、`Op::Blkcall` も揃えた。
`yield` をブロック無しで呼ぶ場合などは BLKCALL に来る前に `LocalJumpError` になり、本家と同じ（スクラッチの `y.rb`）。

テストは `tests/malformed_rite.rs`（新しいファイル。偽の bytecode を扱うテストの置き場がほかに無かった）。image は bintest の `image` lambda と同じ並びで Rust で作り、
opcode の番号は `sabiruby::opcode::Op` から取って、bintest の数（6, 92, 53, 118）と一致することも assert した。

## 決めたこと

- S1 は案 (a)。(b) はしない（探索の意味が表の大きさで変わる本家の都合を真似ることになり、CRuby とも違う）。backlog に残した。
- `hash_get`／`hash_delete` は型を変える（例外を捨てる古い形を残す理由が無い。0.7.0 は挙動の変わるバージョン）。CHANGELOG に移し方。
- 「hash modified」は要素数で見る。本家は表のポインタと容量も見るが、Rust の `Vec` は範囲外を読まないので、要素数（GHSA が足した比較）だけを移した。
- Set は `eql?`／`hash` の例外を「無い」にする（本家の mruby-set が `mrb_protect_error` で not-equal）。
- S2 の `native_mid` は `method_missing`。
- S3 の読み込みの誤りは `VmError::Rite`（本家の `ScriptError: irep load error` ではなく、SabiRuby のほかの読み込みの誤りに揃える）。`OP_BLKCALL` の文言も `OP_CALL` と揃える。
- S7: design の文書にバージョンを書かない。README の数を CI で数え直すのは今回しない（理由は 4 節）。

## 気づいた点

1. **`Set#add` が `eql?` の例外を通す（VM、本家との差）。** `src/builtins/ext_set.rs` の `put` は `vm.hash_set(s, v, Value::True)` で、`hash_set` は `eql?` の例外を返す。
   本家は `kset_equal_value` が not-equal にするので要素が足される。再現: `class Bad; def eql?(o) raise ArgumentError, "boom" end; def hash; "k0".hash end end;
