# 2026-09-23 参照 mruby を 4.1.0-rc から 4.1.0-rc2 に

mruby 4.1.0-rc2（2026-09-11、`c17ffcc24`）が出た。本体の調査（本の repo の
`docs/worklog/2026-09-23-mruby-4.1.0-rc2.md`、`2026-09-23-rc2-migration.md`）では、rc（`3cf73ee`）との差は
GHSA の対処 4 本だけ（`src/hash.c`、`mruby-task`/`mruby-method` の `mrb_gc_protect` の順、`src/load.c` の
`nlocals > nregs` 拒否、`src/vm.c` の `OP_CALL` の型検査）で、`mrbgems/mruby-compiler`、`include/mrbconf.h`、
`mrblib/`、`include/mruby/ops.h` は同一。テストは `test/t/hash.rb` に assert が 1 本増えただけ。
この作業は SabiRuby の参照をそれに合わせる。ブランチ `rc2`、main の `71bb403` から。

## 1. `-utf8` イメージの作り方を残す（`tools/utf8-image/`）

`kishima/mruby:4.1.0-rc-utf8` はリポジトリに作り方が無かった。`docker history --no-trunc` で見ると、
`kishima/mruby:4.1.0-rc` の上に mruby のソースを tar で `/usr/src/mruby-utf8` に置き、
`build_config/default.rb` の `conf.gembox 'default'` の次の行に `conf.cc.defines << 'MRB_UTF8_STRING'` を
`sed` で足した `build_config/utf8.rb` を `MRUBY_CONFIG` にして `rake -j4 && rake install`、最後に
`mruby -e 'p __ENCODING__, "日本語".length, "日本語".size'` で確かめていた。

これを本の `tools/gc-images/gc-experiments.Dockerfile` と同じ形（`ruby:3.2.2-bookworm` から、`ARG MRUBY_VER`、
GitHub から clone して checkout、`--platform linux/amd64`、ローカルのみ）で `tools/utf8-image/Dockerfile` と
`build.sh [tag]`（既定 `4.1.0-rc2`）にした。元のイメージとの違いは 2 つ:

* 土台を `kishima/mruby:<tag>` ではなく `ruby:3.2.2-bookworm` にした。前者はこの機械にしか無いので、
  それを前提にすると作り方が作り方にならない。そのため `/usr/src/mruby`（バイト列版のソース）は入らない。
  中の `mruby` は元のイメージでも utf8 版で上書きされていたので、使う側から見た差は無い。
* `-j4` の 4 は出どころが無いので、`ARG JOBS`（`build.sh` では環境変数 `JOBS`）にし、無ければ
  ビルドする機械の `nproc`。並列度は建てる時間を変えるだけで、建つものは変えない。

`sed` の後の `grep -n MRB_UTF8_STRING` は元のとおり残した。`default.rb` の書き方が変わって置換が空振りしたら、
そこでビルドが止まる。

建てた結果（`tools/utf8-image/build.sh` の最後に同じものを出す）:

## 3. 本家テストの写しを rc2 に

`tools/mrbtest.sh` は `../../ref/mruby` の `test/` と各 gem の `test/`・`mrblib/` を毎回コピーして
`mrbc` にかけるので、`ref/mruby` が rc2 を checkout してある今は、そのまま回せば写しが rc2 になる。
3 つの build（既定、`--bytes`、`--no-regexp`）すべてで回した。

**`.mrb` のバイト一致。** 回す前に追跡している `.mrb` 211 本（`tests/mrbtest` 112、`src/mrblib` 26、
`tests/custom` 21、`tests/fixtures` 18、`bench` 27、`bench/micro` 7）の `md5sum` を取り、3 つの `mrbtest.sh`、
`fixtures.sh`、`custom.sh` の後にもう一度取って比べた。違ったのは `tests/mrbtest/hash.mrb` の 1 本だけ
（`2cc44f38…` → `9fcdc0f9…`、元の `hash.rb` が変わったので当然）。`src/mrblib/*.mrb`（gem の mrblib と core）も
同じバイト列。`tests/mrbtest/src/` の `.rb` で変わったのも `hash.rb` だけで、rc2 の `test/t/hash.rb` と `diff` で一致。

**数。**

| build | 前（rc） | 後（rc2） |
|---|---|---|
| 既定（utf8） | 2344 / 2507（KO 52） | 2344 / 2508（KO 53） |
| バイト列（`--bytes`） | 2267 / 2452（KO 39） | 2267 / 2453（KO 40） |
| mruby-regexp 無し（`--no-regexp`） | 1979 / 2011（KO 10） | 1979 / 2012（KO 11） |

`hash` の行は 3 つとも `44/44` → `45` 件中 `44` ok、KO 1。増えた 1 本が通らない。他のファイルの行は一字も変わっていない。

### 新しい assert が通らない理由

`Hash lookup with entries deleted by an eql? callback`（GHSA-2778-fvwg-5m8w の回帰テスト）は、`hash` が 0 で
`eql?` の中でハッシュの他の要素を消すキーで `[]`、`key?`、`[]=`、20 要素の表の `[]` を引き、4 つとも
`RuntimeError`（`hash modified`）を期待する。SabiRuby では 4 つとも例外が出ず、`assert_raise` 4 本が落ちる
（`sabiruby mrbtest -v` の出力で `Assertion[1]`〜`[4]`、残りの 5 本は通る）。

まず、何が起きているかを本家の rc、rc2 と並べて確かめた（スクラッチの `evil.rb`、`evil2.rb`）。

```
                        rc              rc2                         SabiRuby
[] (hash 0)             nil             RuntimeError: hash modified nil      h は 5 要素のまま
key? (hash 0)           false           RuntimeError                false
[]= (hash 0)            9               RuntimeError                9
20 要素の [] (hash 0)    nil             RuntimeError                nil
eql? の呼ばれた回数     5               1                           0
```

SabiRuby では `eql?` が**一度も呼ばれていない**。本家の小さい Hash（"array" 表現、`ar_get` →
`ea_get_by_key`）はハッシュ値を持たず、全要素に `obj_eql` をかける。だから `hash` が 0 でも `eql?` が走り、
中で消す。SabiRuby は各キーのハッシュ値を `HashData::hashes` に持ち、探索はまずそれを比べる
（`src/object.rs` の `HashData::first_candidate`/`scan_from`、`src/vm.rs:4142` の `hash_index_at`）。
文字列キーの値が 0 になることは無いので候補が 1 つも出ず、`nil` を返す。CRuby も同じくハッシュ値を先に比べる。
つまりこの assert は「小さい Hash は `eql?` を全要素にかける」という本家の表現の都合を前提にしている。

ハッシュ値が一致するキー（`"k0".hash` を返す）で試すと、SabiRuby でも `eql?` は 1 回呼ばれ、中で 4 要素が消える。
その後の探索は `scan_from` が今の長さで区切るので範囲外は読まない（GHSA が塞いだ読み越しはもともと起きない）が、
`hash modified` は出さずに `nil`／`false`／挿入で終わる:

```
                        rc2                         SabiRuby
[] same-hash            RuntimeError, eql? 1 回      nil, eql? 1 回
key? same-hash          RuntimeError                false
[]= same-hash           RuntimeError（size 1）       9（size 2）
```

### 直さなかった理由と案

依頼の条件は「探索・削除の経路に閉じた小さな修正（要素数か世代の比較）で、`cargo test` と全 mrbtest が
前と同じかそれ以上なら実装してよい」。調べた結果、それでは**この assert は通らない**し、小さくも収まらない:

1. 要素数の比較を `hash_index_at` に入れても、`hash` 0 の assert では `eql?` が呼ばれないので何も変わらない。
   assert を通すには、ハッシュ値の比較を飛ばして小さい Hash の全要素に `eql?` をかける、つまり探索の意味を
   本家の AR に合わせる変更が要る。ハッシュ値の違うキーが `eql?` で一致するかどうかが表の大きさで変わる
   （本家の性質）のを真似ることになり、探索の速さ（`docs/design/optimizations.md`、stage 2c）にも触れる。
2. ハッシュ値が一致する場合だけでも rc2 に合わせるには、`hash_index_at` で `key_eql` の前後の `len()` を比べて
   `RuntimeError` を返せばよい。ただし `Vm::hash_get`（`src/vm.rs:4150`）と `Vm::hash_delete`（`src/vm.rs:4526`）は
   `Option` を返して `hash_index` のエラーを捨てているので、`[]`、`key?`、`fetch`、`delete` には届かない（届くのは
   `hash_set` 経由の `[]=` だけ）。届かせるには両者を `VmResult<Option<Value>>` にするか fallible な版を足して
   呼び出し側（`src/builtins/hash.rs` の `[]`、`fetch`、`key?`、`eql?`、ほか）を直すことになり、公開 API
   （`pub fn hash_get`）に触れる。「閉じた小さなもの」を超える。

なので実装せず、`tests/mrbtest/notes.tsv` と `docs/verification/mrbtest-notes.md` に `hash` の行を
「undecided」として足した（分類の一覧にも undecided を足した）。案は: (a) 2 だけ入れる（`hash_get`/`hash_delete` の
エラーを通す変更と合わせて。下の「気づいた点」1 は 2 と同じ修正で直る）、(b) 1 まで入れて本家の AR の意味に揃える、
(c) 違いとして残す（CRuby と同じ意味で、SabiRuby は読み越しを起こさない）。どれにするかは本体か著者が決める。

baseline（`tests/mrbtest/baseline*.txt`）は、生成された表から `--update` と同じ手順で作ったものと `diff` して、
3 つとも変わらないことを確かめた（`hash` の `ok` は 44 のまま）。ファイルは書き換えていない。
`docs/verification/mrbtest*.md` の 3 本は notes を足した後に作り直した。README と `src/lib.rs` の数（2507 → 2508、
2452 → 2453）も直し、README の「残り」の説明に rc2 の 1 本を足した。

## 4. fixtures と custom の参照出力

`tools/fixtures.sh` と `tools/custom.sh` を rc2 のイメージで回した。`.out`、`-bytes.out`、`.rc.out`、`.mrb`、
`src/mrblib/core.mrb`・`require.mrb` は一つも変わらなかった（`git status` と上の `md5sum`）。

変わったのは `.dump` 39 本だが、差分は全部 `irep 0x…` の行のアドレスだけだった（`git diff -U0 -- '*.dump'` から
`irep 0x` の行を除くと何も残らない）。`mrbc --verbose` が irep のヒープ上のアドレスを出し、それが実行ごとに
ASLR で変わる。意味の無い差分なので `git checkout` で戻した（rc の時に作ったものがそのまま rc2 の出力と
アドレス以外一致する）。

`custom.sh` の結果は 17 本が `.expected` と一致、4 本が不一致（`bigint_reference_bugs`、`eval_class_eval_scope`、
`eval_outer_scope`、`utf8_reference_bugs`）。4 本とも本家のバグを書いたケースで、`.rc.out` が rc の時と同じ
なので、rc2 でも本家は直っていない。ヘッダ 7 本の「4.1.0-rc」を rc2 にし、バグを書いた 4 本は
「4.1.0-rc2 (and -rc)」とした。`eval_class_eval_scope.rb` には「master の `300cc9532` はどのタグにも入っておらず、
rc2 も含む（`.rc.out`）」と書いた（`git merge-base --is-ancestor 300cc9532 4.1.0-rc2` が偽）。
`-g` でコンパイルするので行数が変わると `.mrb` の行情報が変わる。ヘッダの行数は変えないように書き、
書いた後にもう一度 `custom.sh` を回して `.mrb` が同じバイト列であることを確かめた。

## 気づいた点

1. **`Hash#[]`／`key?` が `eql?` の例外を捨てる（バグ、VM）。** `Vm::hash_get`（`src/vm.rs:4150`）は
   `hash_index` の `Err` を `_ => None` で捨てる。`hash_delete`（`src/vm.rs:4526`）も `.ok()??` で同じ。
   再現: `bad = Class.new { def eql?(o) raise ArgumentError, "boom" end; def hash; "k0".hash end };
   h = {"k0" => 0}; h[bad.new]` は本家（rc、rc2 とも）で `ArgumentError: boom`、SabiRuby では `nil`
   （`key?` は `false`）。`[]=` は `hash_set` が `?` で通すので本家と同じく例外が出る。3 節の案 (a) と同じ修正。
2. **（6 節で対応済み）`MRUBY_DESCRIPTION`／`MRUBY_RELEASE_DATE` が rc のままだった（VM）。** `src/builtins/object.rs:238,242` は
   `"mruby 4.1.0RC (2026-09-04)"` と `"2026-09-04"`。rc2 は `"mruby 4.1.0RC2 (2026-09-11)"`（`include/mruby/version.h`
   の `MRUBY_PATCHLEVEL_STR` と `MRUBY_RELEASE_DAY` が変わった）。参照に合わせるなら 2 か所の文字列だが、
   Ruby から見える値で、依頼の範囲（`4.1.0-rc` の grep）に無いので触っていない。
3. **`bench.sh`／`ab_micro.sh` の比較相手が rc2 になった（性能の記録）。** rc2 の `hash.c` は探索のたびに要素数を
   覚えて比べるようになったので、`ds_hash` などの本家側の時間がわずかに動くかもしれない。測っていない。
   `docs/verification/bench.md` の過去の倍率は rc が相手。
4. **（6 節で対応済み）`.dump` はアドレスを含むので、`fixtures.sh`／`custom.sh` を回すたびに全部書き換わる（道具）。** 意味のある
   差分が埋もれる。スクリプト側で `irep 0x…` を固定の文字に置き換えれば止まるが、今回は触っていない。
5. **rc2 の他の 2 本（`load.c` の `nlocals > nregs` 拒否、`OP_CALL` の受け手が Proc でなければ `TypeError`）に
   SabiRuby の loader（`src/rite.rs:183` あたり）と `Op::Call`（`src/vm.rs:3705`）が対応しているかは見ていない。**
   本家テストには入っていない（bintest だけ）ので、mrbtest の数には出ない。
6. 本家の rc・rc2 とも `hash` が例外を投げるキーで `h[k]` すると `nil` が返った（`evil2.rb` の最後）。
   SabiRuby も `nil`。本家の挙動の観察としてだけ残す。
