## 1. `Enumerable#hash` と nil の block（`39be934`）

### `Enumerable#hash`

`S = Struct.new(:a); S.new(1).hash` が `NoMethodError: undefined method '__method_recursive?'`。本家の core の mrblib
（`mrblib/enum.rb:374`）の `Enumerable#hash` は `__method_recursive?(:hash)` で循環を見て、`__update_hash(h, i, e.hash)` で畳む。
SabiRuby の `core.mrb` はこの `enum.rb` を含むが、2 つのネイティブが無かった。Struct も、`include Enumerable` した自作のクラスも同じ。

- `Kernel#__method_recursive?(mid, arg2 = nil)`: 本家は `src/kernel.c:228` の `mrb_obj_method_recursive_p`。`ci[-2]` から下へ、
  `mid` が同じで `stack[0]` が受け手と同じ（2 つ目の引数があれば `stack[1]` も）フレームを探す。`ci[0]` は C 関数自身のフレーム、
  `ci[-1]` は呼んだメソッド。SabiRuby では SEND が呼んだネイティブはフレームを積まない（`__defined_cvar?` などが `vm.ci.last()`
  を呼び手として読むのと同じ）ので、一番上のフレームを除いて下へ歩く（`Vm::method_recursive`、`src/builtins/mod.rs`）。
- `Enumerable.__update_hash(hash, index, hv)`: `src/enum.c` の `enum_update_hash`、`hash ^= ((uint32_t)hv << (index % 16))`。
  シフトは 32 ビットで行い、結果を 64 ビットに広げて xor する。`mrb_get_args` の `"i"` に合わせて Integer と Float（切り捨て）を受け、
  ほかは `TypeError`（`String cannot be converted to Integer`、rc2 と同じ文言）。module function（Enumerable の特異メソッドと private の instance メソッド）。

確かめ: スクラッチの `eh.rb`（Struct の hash、自分を含む Struct、自作の Enumerable、Hash と Set のキーとしての Struct、
`__update_hash` の数そのもの 3 つ、型の誤り、`__method_recursive?` を自分で使うクラス）を rc2 と SabiRuby で走らせ、出力が同じ。
hash の値そのものは要素の `hash` が VM ごとに違うので、比べられるのは「同じものは同じ、違うものは違う」と `__update_hash` の式だけ。
これを `tests/custom/enumerable_hash.rb` にした。

### nil の block

`Vm::call_block`／`exec_block` は nil で `LocalJumpError: no block given (yield)` だった。本家の `mrb_yield` などは `check_block`
（`src/vm.c:1821-1829`）で `ArgumentError: no block given`。2 か所をそれに合わせた。Ruby から届く場所を探すため、block 無しで呼べる
ネイティブ 46 個を rc2 と並べた（スクラッチの `nb.rb`）。変える前に違ったのは 5 つ:

```
                 rc2                                             SabiRuby
instance_eval    ArgumentError: wrong number of arguments (given 0, expected 1..3)   ArgumentError: no block given
class_eval       （同上）                                         ArgumentError: no block given
catch            NoMethodError: undefined method 'call' for NilClass   ... for nil
index            Enumerator                                       LocalJumpError: no block given (yield)
define_method    ArgumentError: no block given                    ArgumentError: tried to create Proc object without a block
```

`index` だけが `call_block(nil)` から来ていた。nil の文言を変えると `ArgumentError: no block given` になり、どちらにしても本家と違う。
本家の `mrb_ary_index_m`（`src/array.c:1595`）は引数も block も無ければ `to_enum(:index)` を返すので、`Array#index`／`#rindex` にそれを足した
（決めたこと: 指示の範囲の外だが、nil の文言を変えた結果として Ruby から見える形が変わる場所なので、同じ commit で本家に揃えた）。
残りの 4 つは今回の変更と関係が無く、気づいた点に書いた。nil の文言は Ruby から届く道が無くなったので、公開の `Vm::call_block` を直に呼ぶテストを
`tests/native.rs` に置いた。

## 2. 段階 B の取り込み（`3e6238c`）

B の worklog の「決めたこと」と「気づいた点」を読んでから `git merge --no-ff rel07-scale`。

- **`src/vm.rs` は衝突しなかった。** 本体は `funcall` の `method_missing` のクロージャの枝（A の S2）と、B の SEND の `mid` を引数で渡す形
  （`call_native_direct`／`call_closure_direct` に `mid: Option<Sym>`）が重なると見ていたが、触った行が別だった。A の S2 の枝は
  `call_closure`（`funcall` の道、B は backtrace に数えない方）を使うので、B の新しい引数とは交わらない。task の列（B の S6）も A は触っていない。
  自動で合わさった結果が意味として正しいかは、下の 3 と、全部のテスト（5）で見た。
- **`CHANGELOG.md` と `docs/README.md`** は、同じ場所に A と B がそれぞれ段落を足した衝突だけ。両方残した（A を先に）。
- 合わせた後の `hash_get`／`hash_delete`（A で型を変えた）を B が新しく使っている場所は無かった（build が通る）。

## 3. `op_send` の `method_missing` がクロージャのときの `native_mid`（`91ca672`）

B の気づいた点。`op_send` の「メソッドが無い」の枝は、クロージャの `method_missing` を `call_closure_direct(&f, Some(mm), ...)` で呼ぶ
（B が backtrace のために名前を引数で渡すようにした）が、`Vm::native_mid` は置いていなかった。ほかの SEND の枝（ネイティブ、クロージャ）は
`self.native_mid = Some(mid)` を置いてから呼ぶ。A の S2 で `funcall` の同じ枝は `native_mid = Some(mm)` にしてあるので、2 つの道がずれていた。

先にテストを書いた（`tests/native.rs`、クロージャの `method_missing` が `vm.native_mid` を返す。`1.to_s` の直後に `g.nope` と `relay(g)`）:

```
変更前:  left: ":to_s\n:method_missing\n"     （SEND の道は前に呼んだ `to_s` の名前を見る）
変更後:  ":method_missing\n:method_missing\n"
```

`call_closure_direct` の前に `self.native_mid = Some(mm);` を足した。

## 4. 決めたことと後に回したもの（`db1b8bc`）

- **irep の番号は `unload` の後に再利用しない**（本体が原則で決めた、2026-09-26）。古い番号が別のプログラムを走らせることが決して無いように。
  返した irep 1 つにつき 208 バイト（空の `VmIrep`）が残るのは受け入れる。`docs/design/gc.md` の「Programs」と CHANGELOG に書いた。
- `docs/backlog.md` に 4 行: `eval`／`binding` の irep を返さない（GC で返す形が要る。`eval` を繰り返すプログラムが出たら）、
  backtrace の残りの違いと `instance_exec`・top level の `eval` の中の `__method__`（どちらもフレームの形を変える）、
  記録のイベントが `unload` した irep を指す（表示だけ）、`load_and_run` のプログラムは `unload` できない（1 度読むなら困らない。rubevy の側）。
