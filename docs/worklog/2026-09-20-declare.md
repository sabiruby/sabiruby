## 1. 要るもの（計画書 3.7 と、依頼文）

Ruby が

```ruby
unit :metre, symbol: "m", scale: 1.0
unit :inch,  symbol: "in", scale: 0.0254
```

のように並べた宣言を、ホストが `T: Deserialize` ごとに `Vec<(String, T)>` で受け取る口。
（`item` / `recipe` は利用者の語なので、crate の API・文書・テストには入れない。例は中立の「単位」にした。）

- 名前の重複は既定で `ArgumentError`、Ruby の行番号つき。上書きを許す登録は別の名前の口。
- 欠けたフィールド・型違い・`deny_unknown_fields` のエラーに Ruby のファイル名と行番号が付くこと。
- 走らせ終わってから取り出す口。取り出した後の VM に宣言が残らず、GC のルートを漏らさないこと。
- 読み返し（ホストの表を Ruby から引く）のヘルパ。
- `Vm::set_host_state` は使わない（rubevy が占有）。`sabiruby-serde` は `no_std` なので `Mutex` は無い。

## 2. 置き場所を決める — host store は「目的外利用」か

依頼文は「host store が『型ごとの表』として素直に使えない（`Data` オブジェクト用のスラブなので
目的外利用になる）場合は、実装せず止まって案を報告する」と言っている。`src/host_store.rs` を読んで
確かめたのは次の 4 点で、結論は **素直に使える**（止まる必要は無い）。

1. スラブの中身は「ホストが持つ値」で、`Data` オブジェクトはその値を **Ruby から名指しするための**
   道具でしかない（`src/host_store.rs:1-33` のモジュール説明。`HostStore::insert` 自体は
   `Data` オブジェクトを作らない）。ハンドルを Ruby に渡さなければ、表はただの型ごとの置き場になる。
2. VM が勝手に表へ触るのは 1 箇所だけ — `Vm::host_store_free(tag, handle)`（`:252-256`）が、
   その tag の `Data` オブジェクトが回収されたときに `remove` する。tag は
   `install_host_store` が型ごとに新しく配る（`:222-228`）ので、こちらが `data_new` を呼ばない限り
   その tag を持つオブジェクトは存在せず、VM が表を消すことは無い。
3. GC のルート: 表に入るのは `T: Deserialize` に落とした **Rust の値**と名前の `String` だけで、
   `Value` は 1 つも持たない。クロージャが捕まえるのも `u64` のハンドルとメソッド名の `String`。
   `define_closure` の rustdoc（`src/vm.rs:1326-1328`）が言う「クロージャの中の `Value` はルートに
   ならない」という穴を踏まない。
4. `no_std` で唯一の代案だったクロージャに表を閉じ込める形（`Arc<Mutex<…>>`）は、
   `define_closure` が要求する `Send + Sync + 'static` を `alloc` だけでは満たせない
   （`spin` などの依存を増やすことになる）。host store は VM がすでに持っている道具なので依存が増えない。

払う代償は 1 つ、**使わない `Data` tag を型ごとに 1 つ消費する**こと（`next_tag` が 1 増える）。
u32 の通し番号で、ホストが手で配る番号とぶつからないようにするための仕組みそのものなので実害は無い。
これは rustdoc と `docs/design/serde.md` に書いた。

表の形は「1 つの store に 1 つのエントリ（表そのもの）」にした。「宣言 1 件 = store のエントリ 1 つ」
にすればハンドルを覚えなくて済む（`iter()` が宣言順に並ぶ）が、重複の判定と読み返しが毎回 O(n) の
走査になる。読み返しは control stage が tick の中で引く想定なので、名前 → 位置の索引
（`BTreeMap`、`alloc` にあるので `no_std` で使える）を持てる「1 エントリ = 表」の形を採った。
ハンドルは `Declarations<T>` という token（`u64` + `PhantomData`、`Copy`）に入れてホストが持つ。

### `take` は `remove` ではなく `HostStore::take`

取り出しに `HostStore::remove` を使うと、ハンドルが free list に戻って **次の `insert` で配り直される**
（`src/host_store.rs:115-122` と、モジュール説明の「a handle kept behind the store's back can come to
name a later value」）。同じ VM で同じ `T` をもう一度登録すると、取り出し済みの古いメソッドが新しい表に
書き込むことになる。`HostStore::take`（`:132-138`）はハンドルを `Cell::Out` に置いて番号を返さないので、
これを「貸したまま返さない」形で使った。結果:

- `store.len()` は 0 になり、宣言も名前の索引も VM から出ていく。
- 古いハンドルが別の表を指すことは無い。
- 取り出した後に Ruby がその宣言メソッドを呼ぶと、`is_out` が真なので「もう取り出された」と
  `RuntimeError` で言える（黙って捨てない）。

残るのは空のスラブの枠 1 つ（`Cell::Out`）だけ。「VM に何も残らない」を厳密に言うとここまでで、
報告にも rustdoc にもそう書いた。`HostStore::take` の rustdoc は「借りた側が `restore` する」前提で
書かれているので、返さない使い方をしていることは `declare.rs` のコメントに残した。

## 3. 読み返しの表は「取り出した後の別の表」にした

依頼文の宿題。使われ方は「データ段階を走らせ終わってから、別のスクリプトが tick の中で引く」。
2 つの案:

- (a) 集めたのと同じ表を引く。`take` が要らなくなり 1 つの表で済むが、集める口を開けたままになる
  （control stage のスクリプトが `unit :x` を足せてしまう）し、ホストが検証・派生をした後の表を
  引かせられない。
- (b) `take` でホストが表を受け取り、必要なぶんを `expose` で VM に渡す（**採用**）。

(b) にした理由は 3 つ。第 1 に、宣言と読み返しの間にホストの検証が入るのが普通だから
（rubevy_games の調査 §2 が挙げる「レシピが未知のアイテムを指す」の類。集めた生の表をそのまま
引かせると、検証前の表が Ruby から見える）。第 2 に、データ段階の VM と control stage の VM が
別でもよくなる（`expose` は `Declarations` と独立に、どの VM にも入れられる）。第 3 に、これなら
`take` の後に VM に宣言が残らないという性質を保てる。ホストが同じ表を両方で使いたいときは
`take` の結果を clone して渡せばよく、`expose` に `Clone` 境界は要らない。

読み返し 1 回の中で `to_value_with(vm, &value, …)` を呼ぶには `&mut Vm` と `&T` が同時に要る。
store から借りたままでは通らないので、`RubyClass::take_out` / `give_back` が受け手のためにやっているのと
同じ形 — 表を丸ごと `take` して、変換して、`restore` で返す — にした（`Serialize` は Ruby を呼ばないので
その間に再入は起きない）。`Clone` 境界も `unsafe` も要らない。

## 4. 呼び出し規約で決めたこと

- 引数は 1〜2 個（`vm.check_argc(args, 1, 2)`）。キーワード引数は `native_call_args`
  （`src/vm.rs:4264-4271`。行番号は確認済み）が **中身のあるときだけ**末尾の Hash として渡してくるので、
  `unit :metre` は 1 個、`unit :metre, scale: 1.0` は 2 個で届く。キーワードを 1 つも書かなかった宣言は
  空の Hash を作って `from_value` に渡す（`T` の全フィールドに既定値があれば通り、無ければ
  serde が `missing field` と言う — どちらも Ruby の行番号つきで出る）。
- 第 1 引数は Symbol か String。それ以外は `TypeError`、UTF-8 でない String も `TypeError`
  （crate の「not-UTF-8 は error」に合わせた）。
- 重複の判定は `from_value` より **先**。`unit :metre` を 2 回書いて 2 回目のフィールドも壊れていたら、
  読み手にとっての問題は重複の方なので、そちらを先に言う。
- 戻り値は `nil`。
- `OnDuplicate::Replace` は順番を動かさない（後から書き換える mod が並びを変えない方が読みやすい）。

数（上限・閾値）は 1 つも足していない。宣言の数にも名前の長さにも上限を置いていない
（`docs/design/serde.md` にその旨を 1 行）。引数の 1..2 は数ではなく形。

## 6. 捨てた案

- **`Vm::set_host_state`**: 使わない（rubevy が占有している。計画書 3.7）。試してもいない。
- **`Arc<Mutex<Vec<…>>>` をクロージャに閉じ込める**: `no_std` に `Mutex` が無い。`spin` を足せば書けるが、
  依存を 1 つ増やすし、表が VM の外に出て「VM に何も残らない」を確かめにくくなる。
- **宣言 1 件 = store のエントリ 1 つ**: ハンドルを覚えなくて済むが、重複判定と読み返しが O(n)。
  読み返しが tick の中で走るので索引のある形を採った（§2）。
- **`define_fn` で受ける**: 引数の数が固定になる（`src/convert.rs:440` の `check_argc(args, n, n)`）ので、
  キーワード無しの宣言が通らない。`define_closure`（arity -1）を使った。
- **読み返しで `T: Clone` を要求する**: 表から値を clone すれば借用は解けるが、`RubyClass::take_out` と
  同じ「丸ごと借りて返す」で済んだので境界を足さずに済ませた（§3）。

行番号の確認は `raised()`（`serde/tests/declare.rs:25-34`）が
`describe_error` + `Exception#backtrace` の 1 行目を組んだ文字列を突き合わせる形。実際に出たのは
`missing field \`scale\` (TypeError) at data.rb:2`、
`unknown field \`colour\`, expected \`symbol\` or \`scale\` (TypeError) at data.rb:4`、
`unit "metre" is already declared (ArgumentError) at data.rb:3` など。

測ってから期待値を書いたもの 2 つ:

- **`:in <メソッド名>` は付かない。** 最初は `data.rb:2:in unit` を期待に書いたが、実際は `data.rb:2`。
  例外が抱える backtrace は `keep_backtrace`（`src/vm.rs:2589-2600`）が Ruby のフレームだけを
  記録するもので、ネイティブの名前を足すのは `Vm::backtrace(Some(mid))`（`:2561-2581`）の方だった。
  ファイル名と行番号は要求どおり付くので、期待値を実物に合わせた（§8 に 1 件）。
- **複数行に分けた呼び出しは最後の行**。`unit :metre,` から 4 行に分けた宣言は `data.rb:1` ではなく
  `data.rb:4` で raise する（SEND 命令が持つ行番号）。今回はたまたま問題のフィールドがその行にある。
- **生存オブジェクト数**は、宣言 3 件を走らせて `take` して `gc_collect` した VM と、何も宣言しなかった
  VM とで **完全に一致**した（`the_declarations_hold_no_ruby_object_and_leave_nothing_behind`）。
  スラブに残る `Cell::Out` の枠は heap のオブジェクトではないので `live_count` に出ない。

## 8. 気づいた点

- **`tools/check_no_std.sh` は VM の lib しか見ていない**（`tools/check_no_std.sh:5-6`）。
  `sabiruby-serde` も `no_std` なのに、この crate を `thumbv7em-none-eabi` で建てる確認も
  `serde/src` の `std::` 検査も入っていない。今回は同じ内容を手で走らせた（§7）。
  どこ: `tools/`（今回の担当範囲の外なので触っていない）。属する先: repo の確認の網。
- **同じ VM の 2 つの backtrace が、ネイティブの名前について食い違う。**
  `Vm::backtrace(Some(mid))` は `file:line:in <ネイティブ名>` を先頭に足す（`src/vm.rs:2570-2574`）が、
  例外が抱える方（`keep_backtrace` → `Exception#backtrace`）は Ruby のフレームだけで、ネイティブの
  名前が入らない（`src/vm.rs:2589-2600`）。ネイティブの中で raise したエラーを `e.backtrace` で見せる
  ホストは、どのネイティブで起きたかを行番号から推すことになる。mruby は `mrb_get_backtrace` の側で
  C のフレームを「直下の Ruby フレームの位置」に置いているので、揃える余地はありそう。
  属する先: VM（小さな食い違い、または rustdoc に 1 行）。
- **`HostStore::take` を「返さない」使い方は rustdoc が想定していない。**
  `src/host_store.rs:124-138` は「借りた側が `restore` する」と書いてあるが、番号を手放さずに値だけ
  取り上げる道具としても使える（今回の `take`）。この使い方が想定内かどうかが読んで分からない。
  属する先: VM（rustdoc の言い回し）。
- **計画の前提の小さなずれ**: rubevy_games の調査 §2 は「`item :iron_plate, stack: 100` は
  `(Symbol, Serde<ItemDef>)` で受けられる」と書いているが、`define_fn` は引数の数が固定
  （`src/convert.rs:440` の `check_argc(args, n, n)`）なので、キーワードを 1 つも書かない宣言
  （`item :iron_plate`）はその形では通らない。`define_closure` で 1〜2 個を受ける必要がある。
  属する先: 計画書の前提（rubevy 側の担当が example を書くときに効く）。
- **複数行の宣言の行番号**は最後の行になる（§7）。データファイルを 1 宣言 = 複数行で書くゲームでは、
  エラーの行が「宣言の頭」ではなく「閉じ括弧の行」を指すように見えることがある。
  属する先: 本（移植の章の素材）／rubevy 側の文書に 1 行あると親切。
