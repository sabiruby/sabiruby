# What SabiRuby has

Every class, module and method SabiRuby defines, next to the reference mruby 4.1.0-rc.
`tools/mrbtest.sh` answers *does it behave the same*; this answers *what is there at all*.

Generated by `tools/coverage.sh` on 2026-09-16. Do not edit.
Both sides run the same script, `tools/coverage.rb`, which walks the constants from
`Object` and asks each class and module for `instance_methods(false)` and its singleton
class's `instance_methods(false)`, then sweeps `ObjectSpace` for anything the constants
did not reach. A method is listed **once, under the module that defines it**; `ancestors`
says who inherits it. Private methods are counted too (`private_instance_methods(false)`):
mruby writes a module function as a public singleton method and a private instance method of
the same name, and keeps a good part of `Module` and `Kernel` private, so leaving them out
would turn half the difference between the two VMs into an artefact.
The reference is the `mruby` of the image `kishima/mruby:4.1.0-rc`
(`default.gembox` plus the POSIX gems), the same image `tools/mrbtest.sh` compiles with.

* SabiRuby: `RUBY_ENGINE`/`RUBY_ENGINE_VERSION` = mruby/4.1.0, `MRUBY_DESCRIPTION` = mruby 4.1.0RC (2026-09-04)
* reference: `RUBY_ENGINE`/`RUBY_ENGINE_VERSION` = mruby/4.1.0, `MRUBY_DESCRIPTION` = mruby 4.1.0RC (2026-09-04)

(Both answer `mruby`: what SabiRuby should answer is item 5 of
[`plans/from-mrubyedge-plan.md`](../plans/from-mrubyedge-plan.md).)

344 the reference has and SabiRuby has not:

* **1** are the other half of a module-function pair: the same name on the same
  module, singleton on one side and instance on the other.
* **20** answer here from another ancestor — the same method, a different owner.
* **11** do not answer at all. That is the first list at the end of this file.

And of the 156 SabiRuby has and the reference has not:
**0** are in classes of a not-planned gem, **0** are the other half of a
module-function pair, **39** are the same method on another owner, and
**117** are additions.

The gem a method comes from is not asked per method: mruby tells a script nothing about
where a method was defined (there is no `Method#source_location`, and `Method#owner`
answers the class), so the gem column below is per class and hand-kept in
`tools/coverage.sh`. A gem that adds methods to a core class is invisible in it:
`Kernel.gets` (mruby-io) and `Kernel.printf` (mruby-io) count as core.

What the constant walk could not reach (unnamed classes are singleton classes, which
carry the class methods already listed as `Class.method`):

* reference: ObjectSpace: 0 named module(s) not reachable as a constant, 240 unnamed (singleton or anonymous)
